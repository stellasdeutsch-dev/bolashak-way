# Review rules – Bolashak Way

For the app at the repo root. `site/` is a separate project with its own rules.

Every finding names a file and a line and is marked **Важное**, **Мелочь** or **Было до этого**. The summary starts with the number of findings, or «Проблем нет».

## What breakage looks like here

**Lost progress.** The reader's plan lives only in localStorage. Look for anything that can drop or mix it:
- progress of one programme counted for another (ticks are keyed by stage and item ids shared by all five programmes; the other programmes sit in `archive`);
- a field added to the state but not to `partialize`, the backup file (`buildSnapshot` / `parseSnapshot`), `hydrateFrom` or `sanitizeProgress`;
- a new id (programme, category, date, worker group) not in the `as const` lists in `content/types.ts`, so saved plans with it are dropped on reload;
- a write that can overwrite data it did not read (other tabs, a save that failed to parse).

**The wrong programme's words or sources.** Each platform tells only its own programme. Watch shared stage texts that name one programme, a source of another programme on a platform, `if (track === …)` in components instead of a field in `PlatformMeta`, and figures typed into code instead of read from content (`content/terms.ts`, `categories.ts`). Every figure, deadline and legal wording comes from a source in the registry, word for word – a changed number or paraphrased clause is **Важное** even if it reads better.

**Dates and time zones.** Dates are calendar days (`yyyy-mm-dd`). Breakage: `toISOString()` for "today" (yesterday in Almaty until 05:00), `new Date('yyyy-mm-dd')` without noon UTC, `Intl` without `timeZone: 'UTC'`, memoised "days left" that never moves to the next day, a date saved while it is still being typed, an .ics UID that changes with the date.

**Keyboard and screen readers.** A button that disappears when pressed must hand the focus on; dialogs keep Tab inside and give the focus back; hidden things are `inert`, not only `aria-hidden`; `aria-label` only on elements with a role; status said in words, not only colour.

**390 px.** Nothing wider than the screen and no element that scrolls sideways inside itself: a wide table becomes cards on the phone (`ResponsiveTable`, the requirements matrix). Every button, link and card has a hover style inside `@media (hover: hover)`; no gradients, glow or coloured left stripes; motion off under `prefers-reduced-motion`.

## What to skip

- `site/` – reviewed separately.
- `src/content/lists*.generated.ts` and `faq.generated.ts` – generated by scripts; review the script, not the output.
- Wording of ru/kk/en texts, unless it changes a fact, names another programme or breaks the rules above.
- Style preferences the code already follows consistently (naming, formatting, file layout).

## Nitpicks

At most three **Мелочь** per review – the ones most worth fixing. The rest are not listed.
