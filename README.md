# Bolashak Way

**Живой сайт: https://stellasdeutsch-dev.github.io/bolashak-way/**

Интерактивный роадмап подачи на международную стипендию «Болашак» и на программу «Научные стажировки»: от проверки базовых требований до трудовой отработки после возвращения.

Это **веб-приложение**, а не лендинг и не статья. Пользователь отвечает на четыре вопроса, получает путь под свою категорию и в любой момент видит: где он находится, что уже закрыто и какое следующее конкретное действие.

Приложение **не подаёт документы** за пользователя и не связано с АО «Центр международных программ» — оно структурирует официальные требования и ведёт по ним.

## Что внутри

| Экран | Что делает |
| --- | --- |
| `/onboarding` | 4 вопроса по одному на экран: категория, приглашение, языковые сертификаты, стаж. Кнопка «Назад», без регистрации |
| `/` | Роадмап: прямой вертикальный путь — этапы нанизаны на одну линию, содержание читается слева направо (как программа курса на Coursera или Khan Academy). Липкая шапка с прогрессом, **следующим конкретным действием**, ближайшим дедлайном и оценкой времени, кнопка «Продолжить» |
| `/stage/:id` | Этап: зачем нужен, чеклист, документы, **личные сроки от ваших дат**, официальные сроки, **дословные цитаты из актов** (свёрнуты), типичные ошибки, FAQ, источники, личная заметка |
| `/documents` | Сводный чеклист всех применимых документов с фильтром «Осталось собрать» и ссылками на официальные формы |
| `/settings` | Язык (RU/KK/EN), тема, повторный онбординг, экспорт и импорт прогресса в JSON, сброс с подтверждением |

Ещё есть **поиск** по всему роадмапу (лупа в шапке или клавиша `/`): ищет по этапам, шагам, документам и вопросам — только по тем, что применимы к вашей категории.

Состояние хранится только в `localStorage` браузера. Бэкенда нет. Приложение работает **офлайн** (service worker) и **печатается** на бумагу — чеклист документов и любой этап выводятся без интерфейса, чекбоксами и с адресами ссылок.

## Запуск

```bash
npm install
```

```bash
npm run dev
```

```bash
npm run build
```

```bash
npm test
```

Сборка статическая (`dist/`), `base: './'` — работает с любого подкаталога; роутер хешевый, поэтому GitHub Pages и другие статические хостинги не требуют настройки rewrite.

Приложение развёрнуто на GitHub Pages: каждый push в `main` запускает `.github/workflows/deploy.yml`, который прогоняет тесты, собирает `dist/` и публикует его.

Один нюанс при переезде на другой хостинг: `public/404.html` возвращает пользователя в приложение, если он вручную набрал путь без `#`. В его начале есть константа `BASE_SEGMENTS` — сейчас `1` (проектный сайт вида `user.github.io/repo/`); для собственного домена в корне поставьте `0`.

    language.ts     пороговые уровни приказа № 318

    deadlines.ts    официальные сроки, отсчитываемые от дат пользователя
    excerpts.ts     дословные пункты актов, показываются на этапе в свёрнутом виде
    faq.ts          официальный FAQ + импортированный из CSV

  domain/         ← чистая логика, покрыта тестами
    applicability.ts  движок правил (Rule → boolean по профилю)
    progress.ts       статусы узлов, прогресс, текущий этап, оценка времени
    profile.ts        черновик онбординга → профиль
    documents.ts      документы под профиль
    deadlines.ts      даты пользователя → сроки с отсчётом
    search.ts         поиск по применимому контенту
    freshness.ts      проверка, не устарели ли данные
    exportImport.ts   снимок прогресса в JSON + валидация при импорте
  components/     UI-примитивы, layout, иконки этапов
  pages/          экраны
  i18n/           строки интерфейса и резолвер локалей
  store/          zustand + persist + миграции схемы

### Как работают правила

Видимость этапов, пунктов чеклиста и документов задаётся декларативным предикатом `Rule` прямо в контенте:

```ts
appliesTo: { category: ['master_rural', 'master_medical'] }
autoCompleteWhen: { foreignMeets: true }
```

`domain/applicability.ts` вычисляет их по профилю. Это значит, что **новые правила добавляются без изменения кода** — только в `src/content`.

Поддерживаемые предикаты: `always`, `all`, `any`, `not`, `track`, `category`, `workerGroup`, `invitation`, `hasForeignCert`, `foreignMeets`, `kazakhCert`, `experienceYears`, `continuousMonths`, `meetsExperience`.

## Обновление на новый конкурсный год

Требования «Болашак» меняются каждый год. Порядок обновления:

1. **`src/content/meta.ts`** — поднять `competitionYear` и `lastVerified`.
2. **`src/content/sources.ts`** — обновить ссылки на PDF года: списки вузов (`vuzy2026`), специальностей (`pps2026`, `pps_internship2026`), родственных специальностей (`related2026`), распределение стипендий (`distribution2026`), организации и направления для научных стажировок (`ns_orgs`, `ns_priorities`).
3. **`src/content/categories.ts`** — сверить категории, стаж, GPA и сроки отработки с [Правилами отбора (ПП РК № 573)](https://adilet.zan.kz/rus/docs/P080000573_) и страницей [«Требования к претенденту»](https://bolashak.gov.kz/ru/pretendentu/pravila).
4. **`src/content/language.ts`** — сверить пороговые баллы с [приказом № 318](https://adilet.zan.kz/rus/docs/V1500011258) (Приложение 1).
5. **`src/content/stages/*.ts`** и **`documents.ts`** — сверить сроки, документы и порядок туров.
6. **FAQ из чатов**: положить обновлённый Notion-экспорт в `321/bolashak_faq_baza_notion.csv` и выполнить

```bash
npm run import:faq
```

7. Перевести новые вопросы FAQ на казахский и английский в `src/content/faq.i18n.ts` (тест требует полного покрытия).
8. Прогнать `npm test` — тесты проверяют, что все `sourceId` существуют, у каждой категории непустой роадмап, пороги языков соответствуют таблице, а переводы FAQ на месте.

**Правило контента:** ни одной цифры «по памяти». Каждый факт имеет `source` из реестра, а в интерфейсе везде видны год конкурса, дата сверки и дисклеймер.

- [Приказ № 318: минимальные уровни языков](https://adilet.zan.kz/rus/docs/V1500011258) — adilet.zan.kz
- [Правила отбора и прохождения научных стажировок, ПП РК № 791](https://adilet.zan.kz/rus/docs/P2200000791) — adilet.zan.kz
- Разделы «Претенденту», «Стипендиату», «Выпускнику», «Победителю конкурса», «Визы», «Образцы документов» на bolashak.gov.kz

Практика (с пометкой статуса проверки в интерфейсе):

> Оба CSV не входят в репозиторий (`.gitignore`): в большом файле есть колонка «Автор» с никами участников чатов. Курированные ответы уже собраны в `src/content/faq.generated.ts`, поэтому сборка и тесты работают без этих файлов. Чтобы обновить FAQ, положите свежий экспорт по тем же путям и выполните `npm run import:faq`.

- `321/bolashak_faq_baza_notion.csv` — 20 курированных вопросов-ответов администрации из чатов претендентов (май–август 2026). В приложении они дополнены 20 вопросами, ответы на которые взяты напрямую из официальных документов, — итого 40, и на каждом этапе есть хотя бы один
- `bolashak_voprosy_otvety_notion.csv` — исходный массив 646 сообщений, использован для отбора частотных проблем

## Тесты

```bash
npm test
```

58 тестов в двух файлах.

`src/test/domain.test.ts` — логика: целостность контента (все id источников существуют, нет дублей), применимость по всем 12 категориям, языковые пороги, движок правил, требования по стажу, расчёт прогресса и блокировок глав, следующее действие, онбординг, экспорт и валидация импорта, персональные дедлайны, поиск, свежесть данных, полнота переводов FAQ.

`src/test/ui.test.tsx` — интерфейс: прохождение онбординга за четыре шага, отрисовка всех применимых узлов роадмапа, авто-закрытие узлов по ответам, подтверждение сброса прогресса, поиск из шапки.
